# Changelog

## 2026-10-14

- `signoz_log_pipeline` survives the server reassigning pipeline IDs on every batch save: update and delete match the row by its stable alias/name (delete previously no-oped silently and update failed with "not found in response"), Create/Read keep the plan's filter shape (re-serializing added explicit-zero keys the config never had), and `ModifyPlan` unpins `id`/`created_at`/`created_by` when a change is planned. `order_id` became Optional+Computed — the server assigns the position and renumbers across pipelines, so a required user-pinned value diffed forever.
- `signoz_alert` Create now copies the server's `rule_type` into state: the attribute is Optional+Computed with no Default, so a config that omits it stayed unknown after apply and failed with "Provider returned invalid result object". The other server-supplied fields keep their plan-time defaults.
- `signoz_log_pipeline` `created_at`/`created_by` pin their state via UseStateForUnknown: they were planned unknown on every run, so a freshly created pipeline diffed forever.
- RequiresReplace on `signoz_user.email` and `signoz_auth_domain.name` plus `signoz_notification_channel.name`: the server's PUT endpoints accept these changes with a 204 but keep the stored value (verified against a live server), so an in-place update plan produced "Provider produced inconsistent result after apply" — a rename now plans destroy/create instead. Generated schemas patched pending the upstream skaff knob for per-attribute replacement. `signoz_route_policy.name` was checked and found genuinely updatable, so it stays in-place.
- `signoz_plugin_dashboard.document` no longer pins the pre-update document via UseStateForUnknown: a title/panel update changed the server document, and the stale planned value failed the update with "Provider produced inconsistent result after apply". The attribute now plans unknown on every change and settles from the apply response.

## 2026-10-13

- `signoz_data_retention` logs updates no longer wipe server-side custom retention rules: the server's `SetTTLV2` replaces the whole rule set (an empty or omitted `ttlConditions` passes `validateTTLConditions` and rebuilds the retention expression default-only), so the client now reads the live rule set via `GET /api/v2/settings/ttl` and carries it back into the POST body (kept verbatim when present; a missing v2 endpoint still posts). `model.CustomRetentionRule` documented as the server-mirrored carry-through type.
- `signoz_log_pipeline` now satisfies the server's `PostablePipeline.IsValid`: operator `id` (generated `op-<position>` when absent) and `orderId` (sequence position) are filled in on write — the server rejects operators without them, so provider-managed pipelines previously failed at apply time; the server's `updatedBy`/`updatedAt` response fields are modeled; a config plan modifier compares configs by normalized content so the injected fields never surface as perpetual diffs.
- `signoz_plugin_dashboard` also carries the server's spec-level `links` (dashboardtypes `links,omitzero`) through updates, alongside the dashboard image and per-panel links — same silent-wipe class, caught by the new contract check.
- New `scripts/contract-check` (+ `make contract-check`): feeds the provider's emitted wire JSON into the server's strict request types (`pipelinetypes`/`retentiontypes`/`dashboardtypes`/`gatewaytypes` — `DisallowUnknownFields` + server `Validate`/`IsValid`) and the server's response types back into the provider's client shapes, inside a throwaway module (`mktemp -d`, `replace` directives) so the provider never depends on the server module.
- `signoz_plugin_dashboard` contract hardening: plan-time `ValidateConfig` enforces the server's grid rules (`w`/`h >= 1`, `x`/`y >= 0`, `x + w <= 12`, no overlapping panels, max 100 panels/page, 500 pages/dashboard) and tag rules (max 10; reserved keys `name`, `description`, `created_at`, `updated_at`, `created_by`, `locked`, `source` matched case-insensitively after trim — plain-string tags map to key `tag` and never collide) with per-attribute paths; unset `x`/`y`/`w`/`h` are validated against the builder defaults, so omitted geometry no longer false-fails. Updates are now read-modify-write: the server-owned `image` and per-panel `links` (opaque) are fetched from the live dashboard and carried into the PUT keyed by panel id (`UpdatableDashboardV2`/`PostableDashboardV2`/`GettableDashboardV2` gained contract-accurate `image`, `PanelSpecV2` gained `links,omitzero`); example switched to the shipped `devops-status` plugin (`lax-devops-status`), stub-board example renamed `resource_data_mode.tf`.
- Rebased the fork onto upstream `main` @ `4a205dd` (v0.1.5 lineage): fork resources ported as hand-written services in `internal/services`, transport unified under `apiclients.WrappedClient` (new `DoRequest`), old `signoz/` tree dropped.
- `signoz_plugin_dashboard` rewritten v2-native against `/api/v2/dashboards` (Perses spec, `schemaVersion v6`): the v1 stub path is deleted (no `ToDashboardV1`, no `[plugin-stub-widgets]` suffix, no v1-first/fallback CRUD, no alternate-shape response parsing). Panels are `signoz/WebComponentPanel` objects with plugin versions/elements resolved against the server plugin catalog (`GET /api/v1/plugins`) at apply time; schema adds computed `name`, optional+computed `plugin_version`, and panel `id` now persists the server panels-map key. Strict httptest suite mirrors the server contract (DisallowUnknownFields, required non-nulls, name immutability, `$ref` resolution).
- `signoz_log_pipeline` fix: `GET` now hits `/api/v1/logs/pipelines/latest` — the server registers only versioned read paths, so the old bare `/api/v1/logs/pipelines` read 404'd.
- `signoz_data_retention` fixes: `GET` now reads the `{"status","data"}` envelope (fields live under `data`, not top-level); logs writes use `/api/v2/settings/ttl` with the correct days-based body (`defaultTTLDays`/`coldStorageVolume`/`coldStorageDurationDays`, not `duration_hrs`); metrics/traces use the correct v1 query params (`coldStorage`+`toColdDuration`, not `cold_storage_duration`). All three signals are now written (metrics/traces were silently skipped). New optional `cold_storage_volume` attribute; logs TTL/move must be whole days; a move TTL without a volume is a plan error (the server ignores volume-less moves).
- Docs regenerated from templates + examples via `tfplugindocs` (previously hand-written/stale docs re-rendered; missing `signoz_alert` examples added; `signoz_log_pipeline` example grok pattern escaped for Terraform template interpolation).
- Resource decisions: ours-only `alert`, `plugin_dashboard`, `downtime_schedule`, `data_retention`, `ingestion_key`, `log_pipeline` ported unchanged; collided `dashboard`, `notification_channel`, `route_policy`, `saved_view` keep the fork's legacy-API schemas (upstream's generated new-API versions stay in the tree unregistered, `NewLegacy*` constructors); upstream-only `auth_domain`, `planned_maintenance`, `role`, `rule`, `service_account`, `service_account_role`, `user`, `user_role` come in with the base.
- Adopt upstream v2 for the collided names: `signoz_dashboard`, `signoz_notification_channel`, `signoz_route_policy`, `signoz_saved_view` now register upstream's generated resources/data sources; the fork's legacy implementations (`internal/services/legacy_*`, `internal/legacyclient/{notification_channel,route_policy,saved_view,downtime_schedule}.go`) and their models, attrs, tests, templates and legacy examples are deleted — the upstream `signoz_notification_channel` data-source example is kept for the adopted upstream data source — and `signoz_downtime_schedule` (snake_case keys the server never read) is dropped, examples included, in favour of `signoz_planned_maintenance` — see `docs/guides/migrate-fork-legacy-resources.md`.
- Robot-review fixes on both open PRs: docs re-rendered for the merged schema (Import sections, Sensitive marks and the googlechat/jira/jsmops/incidentio channel configs all present); `signoz_alert` data-source example now looks up by `id`; ingestion-key example outputs only `value`; the migration guide now states the real `signoz_planned_maintenance` `scope` semantics (an expr-lang label expression, not a keyword; empty `alert_ids` = all alerts) and its route-policy examples reference the defined `slack` channel; `alert` `labels`/`preferred_channels` and `plugin_dashboard` `page` descriptions made accurate.

Strict httptest suite mirrors the gateway contract (DisallowUnknownFields against server-shaped bodies, `{"status","data"}` envelopes, typed 404s, zero-time expiry on the wire); migration guide section added for the `rate_limits` split.
